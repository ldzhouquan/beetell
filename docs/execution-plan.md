# BeeTell 执行计划（基于系统设计 v0.3）

> 范围：把 `system-design.md` 的 M0–M4 落为可执行顺序与验收门槛；逐项工作见 [执行 Checklist](execution-checklist.md)。本计划不表示任何实现或实测已经完成。
>
> 依据：[`system-design.md`](system-design.md) v0.3（尤其 §2、§4–§11）；[`system-design-review.md`](system-design-review.md) 是 v0.2 评审存档，若表述冲突，以 v0.3 的 D6–D10 与 §11.3 为准。第 1–10 周是估算，不以赶进度代替验收。

## 1. 交付边界和先决条件

- 一期只交付 Watch PTT 对话、限定场景（单人口述 / 通话 / 面对面 1 对 1）的会议纪要、最小 iPhone 伴侣 App、Mac mini 网关；不做通知捕获、实时字幕、说话人分离、账号/计费/App Store 上架、本地 LLM 推理。
- PTT 默认 `llm-adapter` SSE 流式，`codex-adapter` 到 M2 才接入复杂指令/长任务，不参与 4 秒首句承诺（D5）。ASR、音频、凭据留在本地；BYO 云模型可能接收转写文本，不宣称所有数据不出网（G4）。
- 会议必须**分片到达即增量转写**，`finalize` 只处理末片、合并与可选润色（D6）；PTT 断线丢弃当前话语并提示重说，**仅会议**用 REST `seq` 补传（D9）。一期 TTS 在 Watch 端合成，`tts.chunk` 只预留（D10）。
- 开工准备：可用的 Mac mini、iPhone、用于 M3 验收的 S9+/Ultra、Watch/iOS 开发签名、Tailscale、至少一个 BYO LLM 测试凭据，以及可合法使用的 3 秒中文 PTT 和 10 分钟中文会议测试音频。凭据/真实录音不提交仓库；缺少真机或凭据时对应门槛标记为阻塞，不用模拟结果冒充通过。

## 2. 关键路径与阶段门槛

`M0 可行性/协议定稿 → M1 PTT 纵向闭环 → M2 稳态与可插拔 → M3 会议全管线 → M4 部署与交付`。可并行开发 UI 与后端，但跨阶段验收按以下顺序进行；每一阶段先保留可运行版本，再扩展下一阶段。

| 阶段 / 估时 | 关键交付及前置依赖 | 退出门槛（未达标不得标为完成） |
|---|---|---|
| **M0 / 第 1 周** | 先做四项现场核实：Codex CLI 事件契约；ASR 双口径横评；Watch 双指连点所需 watchOS/手势可行性；S9+/Ultra 灭屏录音存活。另验证 Watch 在家内外经固定 Tailscale `100.x` 地址可达网关（D7）。据此定 AHP v1 帧/错误码/能力确认、网关骨架、Watch 采集 stub、伴侣配置 stub。 | 留下实测记录与选型；会议 10 分钟音频 RTF ≤ 0.5，3 秒 PTT（VAD/短音频方案）转写 ≤ 1 秒；后台录音连续 ≥ 2 小时的 Spike 结果；固定地址实际连通。未通过须记录替代方案及对设计/验收的影响，不能静默改为明文公网或把前台测试算作后台通过。 |
| **M1 / 第 2–3 周** | 基于 M0 协议做 `Watch → AHP REST/WS → ASR → llm-adapter SSE → Watch AVSpeechSynthesizer` 端到端链路；先接通一个 BYO 云模型作为主路径，文本回显与回复分别计时。 | 同一局域网场景（可走固定 Tailscale 地址）连续 10 次 PTT：每次松手→`asr.final` 可见 ≤ 2 秒（G1a），松手→首句 TTS 起播 ≤ 4 秒（G1b）；保存每次时间戳和失败原因。只回显 ASR、没有实际首句回复不算 G1b 通过。 |
| **M2 / 第 4–6 周** | 基于 M1 加重连/取消/错误处理、capabilities 协商及降级、会议 REST `seq` 幂等上传基础、第二类 LLM 接入和 `codex-adapter`（版本锁定、回合事件映射；不改 AHP/客户端）。 | 连续 10 轮 PTT 不崩；`cancel` 后 ≤ 3 秒停止输出；认证/版本错误、能力降级、断线丢弃 PTT、分片乱序/重传/缺口均有测试。新增 adapter 有契约测试，不回归 M1 延迟指标。 |
| **M3 / 第 7–9 周** | 基于 M2 的上传队列做 Watch 会议录音/标记/低电量策略、网关增量转写及 Markdown 纪要、伴侣 App 查看/分享；仅服务约定的近场场景。 | S9+/Ultra 连续 60 分钟会议：期间增量转写不掉片；`finalize`（末片 + 合并/润色）≤ 2 分钟；纪要包含全部标记锚点。补测断网重传、重启续传、乱序、缺口及低电量暂停/续录，不把“末尾集中转写”当作通过。 |
| **M4 / 第 10 周** | 安全配对、doctor、launchd、备份、Tailscale 家内外访问、耗电及隐私收尾；打包自用安装/恢复说明。 | `btell doctor` 五项全绿（端口、ASR 模型、Codex、ffmpeg、凭据可读）；全新 Watch 扫码配对 ≤ 1 分钟；安全与部署检查通过，M1–M3 回归通过。 |

## 3. 实施顺序和依赖说明

1. **先验证不可替代的硬件/网络假设。** M0 的 ASR 延迟、后台录音、手势与固定 Tailscale 地址影响主路径；用真实设备和可重复样本记录环境、时间、版本与结果。若 Watch 无法按 D7 直连固定地址，先确定经 iPhone 转发或其他受保护拓扑、更新设计和测试口径，再继续配对实现；不默许不加密的公网暴露。
2. **冻结客户端/网关边界后再做纵向切片。** M0 确定 `auth{token,v:1}`、`GET /v1/agents`、`POST /v1/sessions` 中 adapter 选择/能力确认、错误码与媒体格式；以契约测试固定行为。处理设计中的文字歧义：§3.2/§4.6/§6.2 对 PTT “续传” 的笼统描述不覆盖 D9；以 D9 为实现准则，并在 M0 定稿时同步勘误源文档。
3. **M1 只打通默认实时路径。** 两个 ASR 队列/实例不互相抢占；PTT 优先、会议转写不被中断。先完成可观测的“松手、asr.final、首个 agent.delta、TTS 起播”时间戳，再优化延迟。Codex 不作为 PTT 4 秒路径的兜底。
4. **M2 把失败路径变成可测契约。** Watch 重连使用退避；PTT 中断即作废并提示重说；会议分片按 `seq` 幂等接收、允许乱序，仅在 `finalize` 对缺口报 4004；网络失败与重放都不得重复计入纪要。`cancel` 及时停止 agent 输出；不支持的 capabilities 走 §4.5 指定降级。
5. **M3 先保证数据完整性，再做纪要质量。** 会议音频 30–60 秒/片，上传即转写入库；标记以时间戳关联原文。验证 Watch 被杀/恢复、低于 20% 暂停及回充后新段续录/合并，再跑 60 分钟端到端；多人远场/说话人分离不在验收范围。
6. **M4 只在安全边界内交付。** 配对码校验后才显示含 token 的二维码；Web 设置页不渲染 config，doctor 脱敏、token 低权限；凭据优先 Keychain，无法读取时仅在显式配置明文兜底且告警。默认走 Tailscale，不开放公网入口；恢复演练包括 launchd 重启、备份与凭据可读性。

## 4. 测试证据与变更规则

- 每个门槛保存：设备/OS/模型/网络及测试样本、运行次数、逐次时间戳或 RTF、失败日志（脱敏）、结果与复测链接；不要把音频、token、API key、完整敏感转写提交仓库。记录位置可在 [Checklist 的验收记录](execution-checklist.md#验收记录) 填入链接。
- 协议契约用自动化测试覆盖鉴权、4001–4004、5001–5003、乱序/重传、capabilities 和 adapter 替换；性能与后台存活需真机实测。每阶段退出前复跑已完成阶段的关键路径。
- 偏离 v0.3 决策（如更换 ASR、改变 Tailscale 拓扑、后台录音降级或放宽验收线）要先记录实测、替代方案及受影响的 D/G/M 条目，再修订设计与本计划；**降级不是原门槛通过**。
- M0 优先收口 §14 未决的 Codex 契约、ASR 选型、双指连点 watchOS 版本；D7 “Tailscale 常开”已拍板，但 Watch 端连通性仍须实测。若 2 小时后台 Spike 不通过，先判定 S9+/Ultra 的 60 分钟 M3 验收是否可达，必要时调整产品范围/门槛并明确记录，不自行宣称 M3 通过。
